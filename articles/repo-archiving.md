## リポジトリ、開けっ放しになってませんか？

GitHub、あるいはその他お使いの Git ホスティングサービスで、ご自身のリポジトリを確認してみてください。その中で、アーカイブしておらず、しかし何年も手つかずのリポジトリはいくつあるでしょうか。

かくいう私も、ちょっと前まで大半のリポジトリを開けっ放しにしていました。その理由は･･･

- 何か思いついて、いつか手を加えるかもしれない
- 誰かが Issue や PR で何か教えてくれるかもしれない
- アーカイブ=放棄って感じがしてちょっとヤダ
- わざわざアーカイブ状態にする意味やメリットを感じない

恐らくは多くの人も、こんな感じの理由に集約されるのではないでしょうか。

でも、よく考えてみてください。最終更新以降、そのリポジトリの改善を気にかけたことはどれだけありますか？誰かが Issue を送ってくれたとして、誠心誠意すぐに対応できるでしょうか？アーカイブされてるあらゆるものに、放棄された無残な姿という印象をお持ちですか？

そして、他人のアーカイブされていないリポジトリを見たとき、「数年間更新されてないけど、ひょっとしたらまだ更新されるのかな」なんて思ったことはありませんか？まあほとんどの場合更新される日は来ないわけですが。

## アーカイブし、終わりを宣言することとは

(アーカイブのしかたは別解説に丸投げするとして) アーカイブしたリポジトリは、このようにアーカイブしたことがわかるように表示されます。

![GitHub repository list](/images/repo-archiving/repo-list.webp)

push もリポジトリ設定も、誰も編集できなくなります。ただし読み込みのみ (Read only) としては引き続き利用可能です。これにより･･･

- リポジトリが動いているか、訪問者も自分自身も一目でわかり、整理整頓になる
- いつか手を加えるかも、という迷いとの決別になる
- これで完成だ、完成だから Issue も PR もストップだという宣言になる

Issue や PR で何か良いモノが来る可能性を締め出してしまうの？と思われるかもしれません。では、もう一度己に問いかけてみましょう。

ふと急に誰かが連絡をくれて、しっかり対応できるか。自分のやる気や許容コストに合わない話が来たとしても、対応 (それも特にお断りの方向で) できるか。

「無理かも」と思ったなら、良い Issue や PR の夢を見るのをやめ、アーカイブを考えましょう。実際、バズった個人開発に届いた Issue や PR が、テンプレート無視だったり我流すぎコードだったりで「勘弁してくれ･･･」って精神削られる事態とかあるらしいです。そう考えると、アーカイブは逃げではなく自己防衛とも言えるのではないでしょうか。

## アーカイブは放棄、ではなく

仮に完成未達だったとしても、続けるのが難しくなったなら「ここまでできて、ここからできてません。難しくなったのでリタイアです」と README に書いて終わっても良いです。失踪やフェードアウトよりよっぽど潔いです。アーカイブしていない方がよっぽど放棄感があります。

もし仮に続けてくれる人が現れたとして、Issue や PR だけがルートではありません。フォークして進めるルートがあります。オリジナル側が「こっちでは終わりです」と言ってくれていたら、続ける側もフォークしやすいはずです。

OSS 界隈におけるバトンタッチとしては、この上なく美しいではありませんか。

## 別にデータが消えるわけでもない

少なくとも GitHub においては、アーカイブ状態を解除することも簡単にできます。アカウントの削除とかデータの削除とかとは違い、アーカイブの操作はそんなに重たいことではないわけです。

ハードルは決して高くありません。メリットも考えられます。動かしていない・動かしそうもないリポジトリを整理・棚卸ししてみませんか？
